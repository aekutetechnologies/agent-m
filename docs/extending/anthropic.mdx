# Anthropic provider (native Messages API)

agent-m ships a native Anthropic client that speaks the Messages API
directly — it does **not** go through the OpenAI-compatible adapter. Enable it
by adding `"type": "anthropic"` to a provider entry in
`~/.agent-m/agent/settings.json`:

```json
{ "providers": [
  { "id": "anthropic", "name": "Anthropic", "type": "anthropic",
    "baseUrl": "https://api.anthropic.com/v1", "model": "claude-sonnet-5",
    "reasoning": true, "apiKeyEnv": "ANTHROPIC_API_KEY" }
]}
```

The key resolves like any other provider (`auth.json` → `settings.json`),
so add an `anthropic` entry to `~/.agent-m/agent/auth.json`:

```json
{ "providers": { "anthropic": { "apiKey": "sk-ant-..." } } }
```

(`apiKeyEnv: "ANTHROPIC_API_KEY"` is a display-only hint — provider-key
environment variables are not read; see [Providers](/extending/providers).)

## Why a native provider

The Anthropic wire format differs from OpenAI-compatible endpoints in ways
the generic adapter cannot express:

- `system` is a **top-level field**, not a `system` role message.
- Tool definitions use `input_schema` (not `parameters`).
- Prefix caching is explicit: `cache_control: { "type": "ephemeral" }`
  breakpoints mark which blocks stay cached between requests.
- SSE events are `content_block_start` / `content_block_delta` /
  `content_block_stop` / `message_delta` (not `choices[].delta`).
- Thinking arrives as `type: "thinking"` content blocks and maps to
  `ContentPart::Thinking` (shown live in the REPL).

## Prefix caching

The provider marks the system prompt and the last text block of user turns
with `cache_control: { "type": "ephemeral" }`, so repeated turns hit the
provider's prefix cache (`cache_read_input_tokens` / `cache_creation_input_tokens`
are parsed into the session usage and shown by `/usage`). Cache
creation is billed at 1.25× input on Anthropic's pricing.

## Models & thinking budgets

See [Models reference](/MODELS) for the full Anthropic model table
(claude-opus-5, claude-sonnet-5, claude-sonnet-4-6, claude-haiku-4-5, …),
context windows, and pricing.

**Current wire behavior** (`anthropic.rs`): every request sends a fixed
`max_tokens: 8192`; thinking is enabled and its blocks map to
`ContentPart::Thinking` (shown live in the REPL). The `/variant` selector
(low/high/max) currently maps to `reasoning_effort` on **OpenAI-compatible**
providers only — it is not wired into the Anthropic provider yet (see
[MODELS](/MODELS) for the planned thinking-budget tiers). `--variant`/
`/variant` are safe to pass; they're simply ignored by the native Anthropic
path today.

## Notes & limits

- Config entries without `"type"` (or with `"openai"`) use the
  OpenAI-compatible adapter — the existing `/provider` wizard writes that
  shape, so Anthropic is configured by editing `settings.json` directly.
- Anthropic forbids `cache_control` breakpoints on image blocks; the provider
  marks the last **text** block of a turn instead.
- Usage accounting merges `message_start` (input/cache tokens) with
  `message_delta` (output tokens) — the session totals stay accurate across
  multi-turn conversations.
