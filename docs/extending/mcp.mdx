# MCP servers (Model Context Protocol)

agent-m is an **MCP client**: any Model Context Protocol server — local
(stdin/stdout) or remote (Streamable HTTP) — can contribute tools to the
agent.

## Configure

Servers live under `mcpServers` in `~/.agent-m/agent/mcp.json` (or
`settings.json`, which `mcp.json` overrides). The shape matches the
cross-tool convention:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path"]
    },
    "remote": {
      "url": "https://mcp.example.com/mcp"
    }
  }
}
```

Each entry needs either `command` (+ `args`, optional `env`) for a spawned
stdio server, or a `url` for a Streamable HTTP server.

## How tools are exposed

At startup agent-m connects to every configured server, runs the JSON-RPC
`initialize` + `tools/list` handshake, and registers each tool as
`<server>__<tool>` (so two servers can share tool names). A banner line
reports the connection:

```
mcp: connected `filesystem` (2 tool(s))
```

The `--tools` / `--exclude-tools` filters apply to MCP tools like any other.

## Safety

MCP tools are **opaque** unless marked read-only: `RiskPolicy` classifies them
**Critical**, so by default every call requires your approval — even under
`--yes` and at autonomy level 4. Two ways to mark a tool read-only so read-like
calls auto-approve (they then drop to the default `Medium` tier):

- **`annotations.readOnlyHint`** — if the server advertises it in `tools/list`,
  agent-m respects it automatically.
- **`readOnlyTools`** — a per-server list of patterns (exact name or `*`
  wildcard) matched against the *bare* tool name (the part after `server__`), for
  servers that don't advertise the hint. Example:

```json
"filesystem": { "command": "rust-mcp-filesystem", "args": ["."],
                "readOnlyTools": ["read_*", "list_*"] }
```

Read-only marking is **advisory**, not a security boundary — a server that
mislabels a mutating tool isn't contained by it. Tool *output* is trusted as the
server reports it; only run servers you control. Writes still prompt as Critical.

## Transports

- **stdio** — LSP-style `Content-Length` framing over the child's stdin/stdout.
- **Streamable HTTP** — JSON-RPC POSTs; SSE responses are consumed until the
  response object arrives.

Requests time out after 30 s (HTTP: 15 s transport-level).
