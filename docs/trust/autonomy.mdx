# Autonomy levels

**Status: shipped.** `AutonomyLevel` 0–4 + `LevelGate` (`crates/agent/src/tool.rs`)
are wired into the CLI: `--level <0-4>` (or `settings.json` `"level"`) selects
the startup level, and `/level N` changes it live during a session via the
gate's atomic handle. Both interactive modes (REPL and daemon) use `LevelGate`.

The design maps the four risk tiers onto approvals:

| Level | Name | Behavior |
|-------|------|----------|
| 0 | observe | Only watches — no tool executes |
| 1 | suggest | Suggests actions but does not run them |
| 2 | assisted | Everything asks for approval |
| 3 | trusted (default) | Auto Low + Medium, asks High + Critical |
| 4 | autonomous | Auto everything except Critical (Critical still asks) |

See `TRUST_AUDIT.md` for the evidence-based audit.

## Relationship to --yes

In the interactive REPL, `--yes` auto-approves Low/Medium calls only.
**High/Critical calls always prompt** — `LevelGate` routes them to the human
regardless of `--yes`. There is no flag that silences the Critical prompt.

In print mode and flows there is no human to ask: risky calls are **denied
outright** even under `--yes` (`DangerousCommandGate`), and without `--yes`
all tool calls are denied.
